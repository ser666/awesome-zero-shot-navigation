# Contributing

Thanks for helping make this list better! Three ways to contribute, easiest first.

> 📐 **Planning to extend the system itself?** Read
> [`ARCHITECTURE.md`](ARCHITECTURE.md) first — it documents the planned
> evolution (configurable sources, MCP server, Zotero integration) and the
> design decisions behind it.

## 1. Suggest a paper (easiest)

Open an [issue](../../issues/new) with:

- **Title + link** (arXiv / DOI / project page)
- If applicable: **code repo** and **project page**
- Optionally: why it belongs here (see the scope below)

We'll fold it in.

## 2. Report a wrong entry

Especially welcome:

- **Wrong venue** — e.g. an arXiv preprint shown as if published at a conference.
- **Wrong code/project link** — this matters a lot: a link to a *different*
  project is worse than no link at all. Our matcher
  ([`scripts/links.py`](scripts/links.py)) is deliberately conservative
  (it prefers to miss rather than mis-attribute), but it can still be wrong.
- **Wrong category / sub-topic** — see [`scripts/topics.py`](scripts/topics.py).
- **Not actually zero-shot navigation** — see the scope below.

## 3. Improve the pipeline (PRs welcome)

The whole pipeline is **plain Python, standard library only** — no
dependencies to install. That's a deliberate constraint (fast, and nothing to
rot), so please keep it that way unless there's a strong reason.

```bash
git clone https://github.com/ser666/awesome-zero-shot-navigation
cd awesome-zero-shot-navigation

# 自测（每个规则模块都自带测试）
python3 scripts/relevance.py     # 相关性过滤
python3 scripts/topics.py        # 分类与子专题
python3 scripts/venues.py        # 会议/期刊归一化与分级
python3 scripts/links.py         # 链接提取 + 代码仓库匹配

# 只重算派生字段（不联网，秒级）
python3 scripts/pipeline.py --backfill

# 增量采集（回看 21 天）
python3 scripts/pipeline.py --days 21

# 本地预览网站
make serve            # → http://127.0.0.1:8210
```

### Common changes and where they live

| Want to change | File | Notes |
|----------------|------|-------|
| What counts as "zero-shot navigation" | `scripts/relevance.py` | **Add a test case**, and run `scripts/impact.py` first (see below) |
| Sub-topic / category taxonomy | `scripts/topics.py` | Order matters — most specific rule first |
| Which venues count as "top" (bolded) | `scripts/venues.py` | CCF-A + major robotics |
| Code-repo matching strictness | `scripts/links.py` | Precision over recall |
| Search keywords | `scripts/sources.py` (`QUERIES_*`) | Grouped: core / task / method. **`QUERIES_BENCH` is not used for search** — code matching only |
| **Add a new data source** | `scripts/sources.py` (`SOURCES` / `EXTRA_SOURCES`) | ⭐ Registration only — **no pipeline changes needed**. See [`OPERATIONS.md` § 如何新增一个数据源](OPERATIONS.md) |
| **Rate-limit interval** | `scripts/sources.py` (`SOURCE_INTERVALS`) | New source with stricter limits → add a line |
| README & site layout | `scripts/export.py`, `docs/index.html` | |

### ⚠️ Tightening the relevance filter? Run the impact check first

```bash
python3 scripts/impact.py        # lists every paper the new rules would drop
python3 scripts/impact.py --brief  # just the counts
```

**Never blind-delete.** For a relevance filter the **cost of a false negative is
much higher than a false positive**: one extra irrelevant entry is a small blemish,
while dropping an important paper is a real, permanent loss (and you'll never
notice). So:

1. Run `impact.py` and **read every entry** it wants to remove.
2. If a legitimate paper would be dropped, your rule is wrong — adjust it.
3. Prefer **"title-only" negative terms** over tightening positive rules.
   A word in the *abstract* doesn't mean the paper belongs to that domain (it may
   be an inspiration, a baseline, or one sensor); the *title* is a strong signal.
   Example: adding `maritime` globally dropped a legitimate unmanned-surface-vehicle
   VLN paper, and `place cells` dropped a brain-inspired robot navigation paper.
4. **Encode both directions as tests**: the cases you reject *and* the near-miss
   cases that must keep passing.

### Rules of the road

1. **Every rule change needs a test case.** Each script has a `__main__` block
   with assertions — add the case that motivated your change. (We've been
   bitten repeatedly by silent rule drift.)
2. **Precision beats recall for links.** If unsure whether a GitHub repo is the
   official implementation, leave it out.
3. **Don't break the zero-dependency rule.**
4. **Don't commit generated files by hand** — `README.md`,
   `docs/data/papers.json` and `data/papers.db` are regenerated by the workflow
   (`scripts/export.py`).

## Scope

**In scope** — papers where an embodied agent navigates to a goal **without
task-specific training**: zero-shot, training-free, open-vocabulary,
foundation-model / VLA-driven, or generalizes to unseen goals or environments.

**Out of scope** — SLAM-only, pure motion planning, classical coverage
planning, web/code/menu "navigation", anything without an embodied agent in a
physical or simulated 3D space.
